# 红绿对位评分（rg-mocap-score）

给"模仿参考视频"的任意产出打分。**不依赖 Blender**，纯 ffmpeg + numpy，两条通道一叠，用 IoU 量化 + 红绿图给人眼验收。

## 何时用

- 做完动捕/动画/重定向后，要量化"和参考视频对上了多少"
- 比较两套方法的产出谁更贴参考（同一参考、同一区间、同一 offset，比均值 IoU）
- 交付前的人工验收辅助（红绿图/GIF 一眼看出哪帧哪里没对上）

## 用法

```bash
python <skill>/scripts/rg_score.py \
  --ref  <参考视频.mp4 或 帧目录> \
  --test <被测帧目录 或 视频> \
  [--offset N]    # 被测帧 i ↔ 参考帧 i+N；参考与被测起始时间不同步时用它对齐
  [--frames A B]  # 只评这个区间（被测侧帧号，1 起）
  [--out DIR]     # 默认 ./rg_out
  [--no-gif]
```

两侧都可以是**视频**（自动抽帧）或**图片目录**（按文件名排序）。分辨率必须一致（不一致先各自缩放）。
Blender 侧产出建议：关掉合成器渲染纯模型帧（`render.use_compositing=False`），背景透明或纯色都行。

### 最小示例

```bash
# 1. 准备参考帧(固定)
python scripts/rg_score.py --ref ref_walk.mp4 --test renders/walk --offset 8 --out score_walk
# 2. 换一套方法重跑, 只改 --test, 用同一 --ref/--offset/--frames 才有可比性
python scripts/rg_score.py --ref ref_walk.mp4 --test cascadeur_export --offset 8 --out score_cascadeur
```

## 输出怎么读

| 文件 | 内容 |
|---|---|
| `report.txt` | 摘要：帧数/均值/中位/最低最高帧 + 最差 5 帧 + 区域分解 |
| `iou.json` | 逐帧 IoU（`{"1": 0.87, ...}`，键是被测侧帧号） |
| `rg/rg_XXXX.png` | 红绿对比帧：**黄=重叠，纯红=参考独有（没跟上），纯绿=被测独有（多余/超前）** |
| `rg.gif` | 红绿动画，验收用 |

颜色语义（写进交付说明时按这个口径）：

- **黄**：对上了
- **一圈红边包着绿**：形状对、位置/姿态有偏差
- **纯红**：参考有、你没有（没跟上）
- **纯绿**：你有、参考没有（多出来/超前了）

## 判读红线（重要，别把 IoU 当唯一真理）

1. **IoU 对"藏在轮廓内部"的肢体不敏感**：侧视图里远侧腿抬起时剪影几乎不变，IoU 可能只波动 ±1%，但人眼一眼看出"腿飘在空中"。**低 IoU 一定有错，IoU 高不代表肢体位置对**。
2. **红绿图才是验收依据**：IoU 用于快速定位区间和比较方法优劣，最终验收看 `rg/` 图或 GIF；有条件让用户在自己视口里核对。
3. **区域分解看趋势**：`report.txt` 里躯干/腿分开报。腿区占比高说明腿的问题大；躯干占比高说明身体/脊柱问题大。
4. **掩码口径固定**：四角 20px 中值当背景色，距离 >40 判前景。被测输出背景要均匀（透明/纯黑/纯灰都行），背景杂乱会污染掩码——那种情况先抠图或改成纯色背景导出。
5. **比较方法要同参**：同一参考、同一 `--offset`、同一 `--frames` 才可比；模型/网格不同的两套产出，IoU 天花板不同（模型形状差异是系统误差，不全是动作问题）。
